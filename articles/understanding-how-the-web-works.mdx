Have you ever wondered what magic happens when you visit your favourite website? Where does the webpage come from? Where does it live? And how does it get to my browser? By the end of this post, you'll understand the basic chain of events that
happens when you enter a URL like `https://cornhub.com` into your browser and hit enter.

## What is a URL?

A **URL (Uniform Resource Locator)** is the address you **type into your browser to visit a website**. It allows our computer to know where to send the message and ask **"Hey, show me what you got!"**.

- **Protocol**: `https://` - The set of rules the computers agree upon. 
- **Host**: `example.com` - The computer we want to talk to. 
- **Path**: `/cat-pics` - The thing we want to get. 
- **Search** `?query=fluffy` - Extra information we can send.

## What is a server?

We’ve entered a URL—but where does that actually go? Well, that URL leads us to a computer somewhere out there on the internet. And in a lot of cases, that computer sends something back—like a website. Hopefully with fluffy cat pics.

A computer that sends back websites, files, or data over the internet is called **a server**.

## How did we find the server?

Now if you look up at the URL, you'll see that `example.com` is the **host**. This tells the browser which server we want to communicate with.

But there's an important step the browser handles behind the scenes called **DNS Lookup**: it converts `example.com` into a unique computer address called an **IP address**.

Every device connected to the internet has one, **even yours**.

### DNS Lookup

To do this, the browser performs a DNS lookup — it takes the domain name `example.com` and **finds the IP address** it's linked to. Try it on your favourite website.

## How the browser talks to the server?

Once the browser knows which computer (server) it wants to talk to, both do a kind of secret handshake to make sure everything’s cool.

This is where **TCP** (Transmission Control Protocol) comes in — it makes sure the browser and server can reliably talk to each other, like a steady phone line.

But there’s a problem: **anyone can listen in** to what we’re sending to the server. So when we use a protocol like `https` we add some security to make sure no one is eaves-dropping. We secure the line by:

- The server proving its identity with a certificate
- Both sides agreeing on an encryption method
- Exchanging keys securely

We call these steps **TLS** — which stands for **Transport Layer Security**. It wraps the conversation in encryption, so no one else can listen in while the browser and server talk.
